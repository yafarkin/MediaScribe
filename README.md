# MediaScribe

MediaScribe превращает аудио и видео в транскрипцию и подробный конспект. Подходит для встреч, интервью, докладов и лекций. Можно разделять говорящих, сохранять кадры со слайдами и экспортировать материал в PowerPoint, PDF и папку для Obsidian. Транскрипция и конспект остаются на языке исходной речи.

`transcribe.py` распознаёт речь через Whisper large-v3. На Apple Silicon используется MLX и Metal, на других системах используется faster-whisper. `summarize.py` анализирует готовую транскрипцию через локальную LM Studio. Скрипты `export_pptx.py`, `export_pdf.py` и `export_obsidian.py` формируют документы из уже подготовленного результата. `prepare.py` скачивает модели распознавания для последующей работы без сети.

Обработка выполняется локально. Интернет нужен при установке зависимостей и скачивании моделей через `prepare.py`. В `transcribe.py` включён режим Hugging Face offline, отключена телеметрия Hugging Face и pyannote. Для анализа слайдов через LM Studio разрешён только числовой loopback-адрес. Перенаправления HTTP и системные прокси отключены.

## Установка на этом Mac

FFmpeg уже установлен. Если устанавливать на другой Mac, сначала выполните `brew install ffmpeg`.

Используйте Python 3.11 или 3.12. Из папки проекта выполните:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m ensurepip --upgrade
python -m pip install -r requirements.txt
python prepare.py
```

`prepare.py` скачивает модель в `models/whisper-mlx`. Нужно несколько гигабайт свободного места. После скачивания можно отключить интернет. Не удаляйте файлы модели.

## Запуск

Запуск без параметров выводит полную справку и значения по умолчанию. То же самое делает `--help`:

```bash
python transcribe.py
python transcribe.py --help
```

```bash
source .venv/bin/activate
python transcribe.py "/путь/Лекция 01.mp4"
```

Для английского используйте `--language en`, для автоматического выбора `--language auto`. Многоязычная модель может распознавать английские вставки в русской речи, но ошибки на переключении языков возможны.

Чтобы передать написание профессиональных терминов и имён, добавьте `--prompt "Термины: ..."`. Это подсказка Whisper, а не команда переписать текст.

Результат появится рядом с исходником:

```text
Лекция 01/
    transcript.md
    transcript.json
    raw-transcript.json
    slides/                 # если указан --slides
    slides.json
    slide-decisions.json
    speakers.json           # если указан --speakers
    Лекция 01.pptx          # если указан --pptx
    Лекция 01.pdf           # если указан --pdf
    summary.md              # если указан --summarize
    summary.parts.json
    obsidian/               # если указан --obsidian
        summary.md
        presentation.md
        slides/
```

Другую родительскую папку можно указать через `--output-root "/путь/результаты"`. В ней также создаётся папка с именем файла без расширения. Существующая папка не перезаписывается. Файлы с одинаковым именем без расширения требуют разных `--output-root`.

## Транскрипция, конспект и экспорты одной командой

Чтобы после распознавания автоматически получить конспект, добавьте `--summarize` и явно выберите модель:

```bash
python transcribe.py "/путь/Лекция 01.mp4" \
  --timestamps paragraph --summarize --summary-model "qwen/qwen3.5-9b"
```

`summary.md` и `summary.parts.json` появятся в той же папке, что и транскрипция. Конспектатор вызывается отдельным Python-процессом через то же окружение. Его живой progress bar виден в терминале. При ошибке конспектатора команда завершается с ошибкой, но готовая транскрипция и слайды остаются на диске.

Флаги `--pptx`, `--pdf` и `--obsidian` включают соответствующие экспорты. В новом запуске любой из них автоматически включает отбор слайдов. Их можно использовать вместе:

```bash
python transcribe.py "/путь/Лекция 01.mp4" \
  --pptx --pdf --obsidian \
  --slides-mode vision --vision-model "qwen/qwen3-vl-4b" \
  --summarize --summary-model "qwen/qwen3.5-9b"
```

Этапы выполняются последовательно: речь, отбор слайдов, PowerPoint, PDF, конспект и папка Obsidian. Выполняются только выбранные этапы. Obsidian создаётся после конспекта, чтобы включить его в итоговую папку. Разные модели LM Studio не запрашиваются одновременно.

Экспортам со слайдами нужна видеозапись. Для аудио можно создавать транскрипцию и конспект без этих флагов.

Параметры конспектатора при вызове из `transcribe.py`:

| Параметр | Соответствует в `summarize.py` | По умолчанию |
| --- | --- | --- |
| `--summary-model` | `--model` | Требуется вместе с `--summarize`. |
| `--summary-prompt-file` | `--prompt-file` | `summary-prompt.md` рядом со скриптами. |
| `--summary-chunk-chars` | `--chunk-chars` | `10000` символов. |
| `--summary-max-tokens` | `--max-tokens` | `4096` токенов ответа. |
| `--summary-timeout` | `--timeout` | `600` секунд ожидания ответа или новых данных потока. |
| `--summary-reasoning` | `--reasoning` | `off`. |
| `--lm-url` | `--lm-url` | `http://127.0.0.1:1234/v1`, общий адрес для слайдов и конспекта. |

Для уже обработанного исходника используйте `--reuse-transcript`. Новое распознавание не потребуется, результат сохранится в отдельную папку `runs`:

```bash
python transcribe.py "/путь/Лекция 01.mp4" --reuse-transcript \
  --pptx --pdf --obsidian
```

В этом случае экспорты используют ранее сохранённые слайды и, для Obsidian, существующий `summary.md`. Если слайдов ещё нет, добавьте `--slides` для нового отбора. Для нового конспекта добавьте `--summarize --summary-model "идентификатор-модели"`.

## Формат таймкодов

Формат Markdown задаётся через `--timestamps`. Исходное время сегментов и слов в JSON сохраняется при любом выборе.

| Режим | Пример | Поведение |
| --- | --- | --- |
| `segment` | `--timestamps segment` | Начало и конец каждого сегмента распознавания, как в первоначальной версии. Выбран по умолчанию. |
| `start` | `--timestamps start` | Только начало каждого сегмента. |
| `paragraph` | `--timestamps paragraph` | Соседние сегменты объединяются в абзацы, время указано у каждого абзаца. |
| `interval` | `--timestamps interval --timestamp-interval 60` | Абзацы с периодическими отметками начала. Отметка ставится у первого абзаца, затем не чаще выбранного интервала. |
| `none` | `--timestamps none` | Абзацы без таймкодов, включая подписи ссылок на слайды. Метки говорящих остаются. |

```bash
python transcribe.py "/путь/Лекция 01.mp4" --timestamps paragraph --paragraph-seconds 45
```

Длительность объединяемого абзаца ограничена `--paragraph-seconds`, по умолчанию 45 секунд. Смена говорящего, пауза больше двух секунд и появление ссылки на слайд разделяют абзацы. Один исходный сегмент длиннее ограничения не разрезается. Это группировка по времени, а не определение смысловых абзацев нейросетью. Периодические отметки привязаны к фактическому началу абзаца, поэтому они не обязаны приходиться ровно на минуту.

Другие распространённые варианты включают время каждого слова, субтитры SRT/VTT и главы по темам. Экспорт этих форматов пока не реализован. Время слов уже сохраняется в `raw-transcript.json`, поэтому его можно использовать для последующего экспорта.

Каждый сегмент распознавания получает начальный и конечный таймкод и метку говорящего. Сегмент Whisper может быть частью реплики или несколькими предложениями. Это не гарантированная граница предложения. При разделении голосов сегменты дополнительно разбиваются по смене говорящего на основе времени слов.

Whisper сам расставляет пунктуацию. Дополнительного литературного редактирования нет, однако распознавание не гарантирует сохранение всех повторов, оговорок и слов-паразитов. На паузах возможен выдуманный текст. Точность терминов и таймкодов нужно оценить на реальной записи.

## Слайды без LM Studio

```bash
python transcribe.py "/путь/Лекция 01.mp4" --slides
```

Скрипт сравнивает уменьшенные кадры, обнаруживает резкие и накопленные изменения и ждёт стабильного изображения. Затем проверяет геометрию контуров. OCR не применяется. Кадры сохраняются целиком в JPG с исходным разрешением; Markdown содержит относительные ссылки.

Геометрическая проверка приблизительна. Она может пропустить слайд с фотографией или принять фон за презентацию. Для отсечения смен камеры используйте режим `vision`.

В обоих режимах отображается progress bar с долей просмотренных кадров и счётчиками `checked` и `saved`. При запросе к LM Studio полоса ждёт ответа модели. Процент относится к просмотру видео, а не к точному оставшемуся времени. Если контейнер не сообщает количество кадров, показывается счётчик без процента.

Параметры отбора:

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `--sample-interval` | `1.0` | Интервал проверки кадров в секундах. |
| `--scene-threshold` | `0.06` | Порог изменения яркости. Уменьшение помогает замечать появление пунктов, но увеличивает число кандидатов. |
| `--settle` | `1.5` | Ожидание стабильного кадра после изменения. |

Короткие слайды между выборками и слайды с постоянной анимацией могут быть пропущены. Время ссылки соответствует сохранённому кадру после стабилизации, а не точному началу перехода. Если слайд появляется посреди сегмента речи, ссылка следует за сегментом и содержит собственный таймкод.

## PowerPoint со словами лектора в заметках

Для нового видео достаточно `--pptx`, а для уже готовой папки результата можно вызвать экспорт отдельно:

```bash
python export_pptx.py "/путь/Лекция 01"
```

Нужны `slides.json`, `transcript.json` и изображения, на которые ссылается `slides.json`. По метаданным `raw-transcript.json` файл получает имя исходного видео без расширения, например `Лекция 01.pptx`. Это работает и внутри папки `runs/<дата-время>`. Без метаданных используется имя папки результата. Другой путь задаётся через `--output`, замена существующего файла разрешается через `--force`.

Каждому сохранённому кадру соответствует один слайд PowerPoint. Кадр вставляется целиком, без обрезки и растяжения. Соотношение сторон презентации берётся из первого изображения; если последующие кадры имеют другие пропорции, по краям остаются чёрные поля. Текст и схемы на кадре остаются частью картинки. Для превращения их в редактируемые объекты потребовался бы отдельный этап распознавания и восстановления структуры.

В начале заметок указан один временной диапазон, например `00:01:20 - 00:02:10`. Дальше идут исходные реплики с метками говорящих, без отдельных таймкодов и технических пояснений. Первый диапазон начинается с нуля, последний заканчивается длительностью записи, сохранённой в метаданных. Для старых данных без длительности используется конец речи, а если он раньше последнего кадра, показывается "конец записи".

Реплика относится к слайду, видимому в середине её временного интервала, и добавляется ровно один раз. Вступление до первого сохранённого кадра относится к первому слайду, а речь после последнего кадра относится к последнему. Реплики на границах слайдов не делятся по словам. Привязка использует время сохранённого кадра, поэтому задержка отбора стабильного изображения также влияет на границу заметок. Одинаковое распределение речи используется в PowerPoint, PDF и Obsidian.

Заметки можно посмотреть и изменить в области Notes/Заметки PowerPoint. Для создания файла не нужны установленный PowerPoint, облачные сервисы или LM Studio. При экспорте также отображается progress bar по числу слайдов. Для переустановки зависимостей после обновления проекта выполните `python -m pip install -r requirements.txt`.

## PDF со слайдами и текстом

При обработке видео добавьте `--pdf`. Для готовой папки результата используйте отдельную команду:

```bash
python export_pdf.py "/путь/Лекция 01"
```

Результат называется `Лекция 01.pdf` по имени исходного видео. Каждый слайд начинает новый раздел на новой странице A4. Вверху указан номер слайда и один временной диапазон, затем идёт кадр целиком, а под ним реплики без отдельных таймкодов. Если текст длинный, он продолжается на следующих страницах с обычным размером шрифта. Текст остаётся доступным для поиска и копирования.

Экспорт выполняется через Python и ReportLab. PowerPoint и LibreOffice для него не требуются. Шрифт встраивается в PDF; на Mac и Windows используется локальный Arial, на Linux ищется DejaVu Sans или Liberation Sans. Другой TTF можно указать через `--font-file "/путь/font.ttf"`, а при запуске из `transcribe.py` через `--pdf-font-file`. Шрифт должен содержать символы исходного текста. Параметры `--output` и `--force` работают как в экспорте PowerPoint.

## Папка для Obsidian

При обработке видео добавьте `--obsidian`. Для готового результата:

```bash
python export_obsidian.py "/путь/Лекция 01"
```

В папке результата появится самостоятельная папка `obsidian`:

```text
obsidian/
    summary.md
    presentation.md
    slides/
```

`summary.md` содержит название, описание материала, имя исходного файла и ссылку на `presentation.md`. Если рядом с исходной транскрипцией есть готовый `summary.md`, его содержимое также включается. Без него создаётся описание и ссылка, без нового запроса к модели. Для подробного конспекта используйте вместе `--summarize` и `--obsidian`.

`presentation.md` содержит все выбранные слайды и привязанные к ним реплики. У каждого слайда один временной диапазон, изображение и текст без отдельных таймкодов. В начале есть обратная ссылка на `summary.md`. Изображения копируются внутрь экспортируемой папки, ссылки относительные.

Скопируйте папку целиком в любое хранилище Obsidian. Исходное видео и рабочая папка MediaScribe для чтения не нужны. Obsidian не требуется устанавливать для самого экспорта. Другую папку можно выбрать через `--output "/путь/новая-папка"`. Существующая папка не перезаписывается; выберите новый путь или новый запуск через `--reuse-transcript`.

## Слайды через LM Studio с учётом речи

В LM Studio загрузите локальную модель с поддержкой изображений. Обычная текстовая модель не подходит. Включите локальный сервер и возьмите идентификатор модели из LM Studio. Укажите его в команде:

```bash
python transcribe.py "/путь/Лекция 01.mp4" \
  --slides --slides-mode vision --vision-model "идентификатор-модели"
```

По умолчанию запросы идут на `http://127.0.0.1:1234/v1`. Другой локальный порт задаётся через `--lm-url`. При включённой авторизации LM Studio задайте переменную окружения `LM_STUDIO_API_KEY`.

Модель получает кадр-кандидат, последний принятый слайд и текст примерно за 20 секунд до и после кадра. Она проверяет наличие учебного материала и изменение содержания, чтобы отсеивать смену говорящего, камеры и возвращение к тому же слайду. Изображения для проверки уменьшаются до ширины 1280 пикселей, сохранённые JPG остаются в полном разрешении. Речь и изображения передаются только локальному серверу.

Модель не редактирует транскрипцию и не извлекает текст со слайдов. Её решения записываются в `slide-decisions.json`. При ошибке сервера или некорректном ответе выполнение останавливается; уже готовая транскрипция сохраняется. Точность отбора зависит от модели и записи. Анализ не находит слайды, которые не попали в кандидаты первого этапа.

На Mac с 24 ГБ памяти сначала попробуйте небольшую модель с поддержкой изображений в 4-битном формате. Транскрипцию и проверку слайдов можно запускать отдельно, чтобы освобождать память между этапами. Подходящий размер и качество модели нужно проверить на ваших кадрах.

## Повторная обработка слайдов

Первый запуск можно сделать без слайдов. Затем загрузите модель изображений в LM Studio и выполните:

```bash
python transcribe.py "/путь/Лекция 01.mp4" --reuse-transcript \
  --slides --slides-mode vision --vision-model "идентификатор-модели"
```

Распознавание речи повторяться не будет. Результат сохраняется в `Лекция 01/runs/<дата-время>/`, предыдущий результат остаётся на месте. При изменении исходного файла кэш отвергается. Язык, модель и подсказка Whisper при повторном использовании кэша не меняют ранее распознанную речь.

Повторный запуск подходит и для изменения вида таймкодов без нового распознавания:

```bash
python transcribe.py "/путь/Лекция 01.mp4" --reuse-transcript --timestamps none
```

Если в исходной папке результата уже есть слайды или разметка говорящих, они сохраняются и в новом варианте. `--slides` запускает новый отбор кадров, а `--speakers` заново определяет говорящих.

## Подробный конспект через LM Studio

Запустите локальный сервер LM Studio на `127.0.0.1:1234` и выберите текстовую модель. Модель с поддержкой изображений для конспекта не требуется. Скрипт использует только Python и уже установленный `tqdm`, отдельный SDK не нужен.

Узнайте идентификаторы доступных моделей:

```bash
python summarize.py --list-models
```

Список `/v1/models` может включать скачанные модели, которые сервер загрузит при первом запросе. Укажите модель явно:

```bash
python summarize.py "/путь/Лекция 01/transcript.md" --model "qwen/qwen3.5-9b"
```

Вместо файла можно передать папку с `transcript.md`, обычный текст `.txt`, `transcript.json` или `raw-transcript.json`. Результат для файлов `transcript.*` и `raw-transcript.json` записывается в `summary.md` рядом с исходником. Для другого имени, например `lecture.txt`, создаётся `lecture.summary.md`. Параметр `--output "/путь/конспект.md"` меняет выходной путь.

Промпт лежит рядом со скриптом в `summary-prompt.md`. Его можно редактировать или выбрать другой через `--prompt-file`. Он запрашивает обзор, основные тезисы, подробный план, определения, примеры, методы и формулы, практические выводы и вопросы с ответами для повторения. Разделы без материала должны пропускаться. Модель получает инструкцию использовать только лекцию, сохранять оговорки и неопределённости, а также не выдумывать факты и таймкоды.

Язык берётся из метаданных распознавания, если они доступны. Для обычного текста модель определяет основной язык по исходному фрагменту. На каждом этапе ей передаётся требование писать на языке оригинала, включая заголовки. Конспект создаёт нейросеть, поэтому факты, полноту и язык результата нужно проверять по исходнику.

Длинный текст делится на части, по умолчанию не более 10000 символов. Сначала создаются подробные заметки по каждой части, затем они объединяются в итоговый конспект. При необходимости используются дополнительные этапы объединения. В `summary.parts.json` сохраняются успешные промежуточные ответы и использованный промпт. Части помогают проверить, какие детали не попали в итоговый текст. Они сохраняются и при сбое последующего запроса; автоматического продолжения с места остановки пока нет.

```bash
python summarize.py "/путь/Лекция 01/transcript.md" \
  --model "qwen/qwen3.5-9b" --chunk-chars 8000 --max-tokens 4096
```

`--chunk-chars` ограничивает размер исходного материала в символах, а не токенах. Помимо материала в контекст входят промпт, небольшой фрагмент оригинала для сохранения языка и ответ модели. Подберите окно контекста в LM Studio с учётом этих затрат. При переполнении уменьшите `--chunk-chars`; при обрезанном ответе увеличьте `--max-tokens` и окно контекста либо уменьшите часть. Скрипт сообщает обрезанный ответ как ошибку вместо записи незаконченного конспекта.

`--timeout 600` задаёт таймаут ожидания ответа или новых данных потока. Итоговый файл появляется после успешного окончания всех этапов. Существующие файлы не заменяются без `--force`; исходную транскрипцию нельзя заменить даже с этим флагом.

Конспектатор получает поток событий LM Studio. Общая полоса показывает завершённые этапы и их текущий план. При дополнительных этапах объединения количество этапов уточняется. Вторая строка показывает загрузку модели, процент обработки запроса и число уже полученных символов во время генерации. Точный размер будущего ответа неизвестен, поэтому для самой генерации показывается живой счётчик, а не выдуманный процент. При обрыве потока незавершённый ответ не считается готовым конспектом. Прогресс одинаково работает при отдельном запуске `summarize.py` и при `transcribe.py --summarize`.

Конспектатор использует нативный endpoint LM Studio `/api/v1/chat` с `reasoning=off` и без сохранения серверной истории. На проверенной сборке LM Studio совместимый endpoint игнорировал `chat_template_kwargs.enable_thinking=false`, поэтому для конспекта выбран нативный API. Если модель не поддерживает переключение reasoning, укажите `--reasoning auto`. Нужна версия LM Studio с `/api/v1/chat`. Для подробных конспектов начните с контекста 32k либо уменьшите части, например до `--chunk-chars 5000`; допустимый размер зависит от модели и доступной памяти.

Адрес сервера можно изменить через `--lm-url http://127.0.0.1:1234/v1`. Если в LM Studio включена авторизация, задайте `LM_STUDIO_API_KEY`. Оба скрипта используют общий локальный клиент `lmstudio.py`, который запрещает удалённые адреса, системные прокси и HTTP-перенаправления.

Конспект и проверку слайдов разными моделями запускайте последовательно. Если в LM Studio включена автоматическая выгрузка предыдущей модели при загрузке следующей, параллельные запросы могут прерываться с ошибкой `Model unloaded`. Изменение контекста с перезагрузкой модели тоже следует делать между запусками.

## Несколько голосов

Для текущих лекций с одним голосом `--speakers` не нужен. Для записей с несколькими людьми установите дополнительный пакет:

```bash
python -m pip install -r requirements-speakers.txt
```

Примите условия [pyannote Community-1](https://huggingface.co/pyannote/speaker-diarization-community-1) и создайте токен Hugging Face с правом чтения модели. Передайте его через переменную `HF_TOKEN` при скачивании:

```bash
python prepare.py --speakers
python transcribe.py "/путь/Обсуждение.mp4" --speakers
```

Если число участников известно, добавьте `--num-speakers 2`. На Mac pyannote выполняется на CPU. Метки `Спикер 1`, `Спикер 2` действуют в пределах одной записи. Одновременная речь и короткие реплики могут распознаваться неверно. Используется exclusive diarization: каждой части текста назначается один говорящий, разделение одновременно звучащих голосов не выполняется. Если перекрытия с найденным голосом нет, ставится метка `Спикер не определён`.

## Windows

Исходный Python-код общий, но окружение нужно установить отдельно. Нужны Python 3.11/3.12, FFmpeg в `PATH` и пакеты из `requirements.txt`. Там автоматически выбирается faster-whisper вместо MLX. Выполните `python prepare.py` на Windows для скачивания соответствующего формата модели. Активация окружения в PowerShell: `.venv\Scripts\Activate.ps1`.

На CPU скрипт работает с параметрами по умолчанию. Для RTX 4070 используйте `--device cuda`; дополнительно нужны совместимые библиотеки CUDA/cuDNN согласно [инструкции faster-whisper](https://github.com/SYSTRAN/faster-whisper#gpu). Windows и CUDA в этой рабочей среде не проверялись.

## Проверки

```bash
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
```

Проверки используют FFmpeg и искусственные аудио и видео. Они проверяют извлечение звука, запись результата, повторное использование кэша, распределение слов по голосам, форматы таймкодов, ссылки на слайды и progress bar. Проверки конспектатора покрывают разбиение текста, передачу языка на всех этапах, сохранение промежуточных результатов, streaming-события, обрыв потока и вызов из `transcribe.py`. Проверки экспортов читают PowerPoint и PDF обратно, проверяют заметки, имя исходного видео, кириллицу и продолжение длинного текста. Папка Obsidian проверяется после перемещения вместе с изображениями. Нейросети в автоматических проверках не запускаются.
